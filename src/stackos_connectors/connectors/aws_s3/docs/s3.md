# Amazon S3 protocol

Source: [reviewed source contract](https://github.com/flowmonkeyio/StackOS/blob/3121f4af370fbad273d08a9469d8961de2278534/docs/integration-contracts/s3.md).
Condensed during extraction on 2026-10-05; provider documentation was not
reverified live. Installed actions and schemas are defined by the catalog.

S3 general-purpose buckets have a flat object-key namespace. Prefixes and
zero-byte trailing-slash markers are not native directories. Normalize a
tree prefix with its trailing slash so `reports/` does not match
`reports-old`. Preserve opaque ListObjectsV2 continuation tokens and decode
URL-encoded keys exactly; each listing remains a bounded page.

IAM capabilities differ by operation: listing needs `s3:ListBucket`, reads
need `s3:GetObject`, upload/copy destinations need `s3:PutObject`, current
object deletion needs `s3:DeleteObject`, and incomplete multipart cleanup
needs `s3:AbortMultipartUpload`. KMS-encrypted objects can need KMS permissions.
A successful list does not prove write or cleanup permissions.

Conditional writes distinguish destination absence (`If-None-Match: *`)
from replacement. A precondition conflict is a known failure or skip, not
permission to resend an unconditional write. Downloads must preserve the
selected local destination boundary when projecting object keys.

Multipart completion is the visible write boundary. Failure before completion
can require abort; one successful abort response does not prove every in-flight
part is gone. Preserve the upload ID, completed parts, cleanup errors and
uncertain outcome separately. AWS documents ListParts verification and
potentially repeated aborts.

S3 has no atomic rename. Copy followed by source delete can leave both objects
when deletion fails. Preserve both stages and source identity conditions; do
not erase the destination as an assumed rollback. An ETag condition is not a
version-specific delete: a concurrent replacement with the same ETag remains
a residual race. Deleting the current key in a versioned bucket can create a
delete marker while retaining historical versions; it is not a version purge.

Preserve AWS error codes, HTTP status, request IDs, VersionId, DeleteMarker,
partial item results and retry uncertainty. Do not blindly repeat a mutation
after a transport failure whose outcome is unknown.
